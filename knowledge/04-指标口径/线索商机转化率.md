# 指标：商机转化率（线索→商机→成交）

> 归属：`crm-metric` · docKey：`crm/metric/lead-opportunity-conversion` · 证据基线：zhgj-crm-server（2026-11）

## 一句话口径

转化率是**四个比率**，统一算法 `round(分子 / 分母 × 100)`，单位为整数百分比：

| 指标 | 公式 | 业务含义 |
|---|---|---|
| 线索转商机率 | 商机数 ÷ 线索数 | 线索质量 |
| 商机转成交率 | 合同数 ÷ 商机数 | 销售转化能力 |
| 中标转线索率 | 线索数 ÷ 中标数 | 招标转化 |
| 中标转成交率 | 合同数 ÷ 中标数 | 招标成交效率 |

## 计算代码

```java
// BusinessMapServiceImpl.java:52-57
vo.setWinBidToClueRate(     calculateRate(vo.getClueNumber(),      vo.getWinBidNumber()));
vo.setClueToBusinessRate(   calculateRate(vo.getBusinessNumber(),  vo.getClueNumber()));
vo.setBusinessToAgreementRate(calculateRate(vo.getAgreementNumber(), vo.getBusinessNumber()));
vo.setWinBidToAgreementRate(calculateRate(vo.getAgreementNumber(), vo.getWinBidNumber()));
```

取整与边界（`BusinessMapServiceImpl.java:66-76`）：

```java
private int calculateRate(Integer num1, Integer num2) {
    int n1 = num1 == null ? 0 : num1;   // 分子
    int n2 = num2 == null ? 0 : num2;   // 分母
    if (n1 > n2)        rate = 100;     // ★ 分子大于分母时按 100% 处理
    else if (n2 > 0)    rate = (int) Math.round(((double) n1 / n2) * 100);
    else                rate = 0;       // 分母为 0
    return rate;
}
```

**三个必须记住的边界**：① 四舍五入到整数；② 分子 > 分母直接钳到 100%；③ 分母为 0 返回 0（不是 null，也不报错）。

## 分子分母分别取什么

来源：`BusinessMapMapper.xml` 的 `salesOverviewStatistics`。

| 指标 | 实际取数 |
|---|---|
| 合同数 `agreementNumber` | `COUNT(0)` on `t_agreement`，条件 `IS_DELETE=0 AND BUSINESS_TYPE=1 AND AGREEMENT_STATUS=1`，按 `SIGN_DATE` 过滤，并经 `t_project_info.AREA_CODE` 关联到区域 |
| 商机数 `businessNumber` | `在途商机数 + 失单商机数`（`biz.businessNumber + failBiz.businessFailNumber`） |
| 线索数 `clueNumber` | `在途线索数 + 失单线索数 + 失单商机数`（`clue.clueNumber + failBiz.clueFailNumber + failBiz.businessFailNumber`） |
| 中标数 `winBidNumber` | `win` 子查询（招标/中标数据） |

## 口径陷阱（必读）

1. **合同数用的是合同档案表，不是订单表**：`t_agreement`（`AGREEMENT_STATUS=1, BUSINESS_TYPE=1`）≠ `t_clue_contract`。所以"商机转成交率"和"合同金额"指标里的合同不是同一个集合，**不能互相反推**。
2. **商机数含失单**：`businessNumber` 是在途 + 失单。如果误以为只算在途，会得出偏高的转化率。
3. **线索数含失单商机**：分母里混进了"已失单商机数"，因为一个商机对应一个线索，失单商机也算线索走完了流程。
4. **分子大于分母时被强制钳到 100%**：出现 100% 不一定是真的 100%，可能是数据口径不一致（比如合同跨期、线索跨期）触发了保护分支。看到清一色 100% 要警惕。
5. **整数百分比**：63.4% 会显示 63%，做趋势分析时四个季度的取整误差会累积。
6. **分子分母的时间窗口来自不同对象**：合同按 `SIGN_DATE`，线索/商机按各自业务日期。跨期数据和分母对不齐是正常现象。
7. **区域维度靠 `FIND_IN_SET`**：区域树用 `AREA_CODE` + `NODE_ROUTE` 做上下级展开（`JOIN t_area child ON FIND_IN_SET(ar.AREA_CODE, child.NODE_ROUTE) > 0`），不是递归 CTE。

## 数据源表

| 表 | 作用 |
|---|---|
| `t_clue` | 线索（线索数） |
| `t_clue_business` | 商机（商机数，含失单） |

| `t_project_info` | 项目，用于把合同归到区域 |

## 维度

区域（层级展开）/ 部门 / 时间区间 / 金额类型（万元或亿元）。

## 验证路径

1. 页面：商机地图 / 销售概况（`pages/businessOpportunityMap`，接口 `/app/businessMap`）；
2. 数据库：分别数线索、商机、合同档案三张表；
3. 差异排查：先看分子分母是否含失单 → 再看是否触发 100% 钳制 → 最后核时间窗口。

## 常见问题

- **Q：商机转化率怎么算？** 商机数 ÷ 线索数 × 100，四舍五入取整。
- **Q：为什么转化率显示 100%？** 可能触发"分子>分母按 100%"的保护分支，需核对口径而非直接采信。
- **Q：商机转成交率里的"成交"指什么？** 指合同档案（`t_agreement`，审批通过且业务类型=1），不是销售订单 `t_clue_contract`。
- **Q：转化率能被 0 除吗？** 分母为 0 时返回 0，不报错。
