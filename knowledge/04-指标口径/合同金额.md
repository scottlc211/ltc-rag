# 指标：合同金额（签约额 / 订单总金额）

> 归属：`crm-metric` · docKey：`crm/metric/contract-amount` · 证据基线：zhgj-crm-server（2026-11）

## 一句话口径

统计区间内，**所有处于"审批通过及之后履约状态"的销售/代理/备货合同，其含税金额之和**；归属日期取签约时间，签约时间为空则回退到审批完成时间。

## 计算公式

```sql
-- DataBoardMapper.xml:6-22（revenueOverview 的 contractTaxAmount）
SUM(cc.TAX_TOTAL)
FROM t_clue_contract cc
LEFT JOIN t_process_result pr ON cc.PROCESS_RESULT_ID = pr.PROCESS_RESULT_ID
WHERE cc.is_delete = 0
  AND cc.CONTRACT_STATUS IN (1, 11, 12, 13, 14, 15)
  AND IFNULL(cc.SIGN_TIME, pr.REDULT_TIME) BETWEEN #{startTime} AND #{endTime}
```

按业务类型过滤（同一 SQL 的参数分支）：

- `type = 1` → `cc.BUSINESS_TYPE = 1`（销售/直营）
- `type = 2` → `cc.BUSINESS_TYPE IN (2, 3)`（代理 + 备货）

## 取值规则拆解

| 要素 | 规则 | 为什么 |
|---|---|---|
| 金额字段 | `TAX_TOTAL`（含税总额） | 报表口径是含税；不要拿它当不含税用 |
| 状态 | `IN (1,11,12,13,14,15)` | 1 审批通过 + 11 待签约 + 12 待履约 + 13 履约中 + 14 完成 + 15 终止。排除 0 审批中 / 2 驳回 / 4 撤销 / 5 作废 |
| 已删除 | `is_delete = 0` | 漏了会让金额虚高（典型坑） |
| 归属日期 | `IFNULL(SIGN_TIME, REDULT_TIME)` | 没填签约时间时，用审批完成时间兜底 |
| 单位 | 源表原值 ÷ 10000 = **万元** | `DataBoardServiceImpl.formatAmount()` 统一除 10000，保留 2 位 |

> 注意 `REDULT_TIME` 是库里真实的**拼写错误**（不是 `RESULT_TIME`），写 SQL 时照抄，别"纠正"。

## 数据源表

| 表 | 作用 |
|---|---|
| `t_clue_contract` | 合同/订单主表（含 `TAX_TOTAL`、`CONTRACT_STATUS`、`SIGN_TIME`、`BUSINESS_TYPE`） |
| `t_process_result` | 审批主单，提供 `REDULT_TIME` 兜底 |

## 维度

销售 / 部门 / 区域 / 业务类型（直营 1、代理 2、备货 3）/ 时间（日、周、月、季、年）。

## 口径陷阱（必读）

1. **同一指标在两张报表里算法不一致**：
   - 营收看板用 `IFNULL(SIGN_TIME, REDULT_TIME)`（有兜底）；
   - 员工业绩用 `cc.SIGN_TIME BETWEEN ...`（**没有兜底**，`DataBoardMapper.xml` 的 `performanceStatistics:108`）。
   - 后果：一批"审批通过但没填签约时间"的合同，会计入看板合同额、但不计入个人业绩。**两边对不上时先查这个。**
2. **直营与代理/备货的合计口径不同**：不传 type 时三类全算；传 2 时会同时把备货(3)算进去，看起来像"代理金额偏大"。
3. **合同变更没有冲减**：变更记录（`t_clue_contract_change_record`）产生负向金额，但这条 SQL 只读主表，**不会自动扣减**。需要冲销口径时得单独处理变更表。
4. **"合同"有两张表**：本指标用 `t_clue_contract`（订单）；销售概况里的"合同数"用 `t_agreement`（合同档案）。两个"合同金额"可能不同。
5. **含税 vs 不含税**：`TAX_TOTAL` 是含税。若业务问"不含税收入"，不能用这个字段直接答。
6. **已作废要排除**：`CONTRACT_STATUS = 5` 不在集合内，作废单不计入——这是有意的。

## 验证路径

1. 页面：`statisticalAnalysis` → 数据中心 → 合同台账（`contractLedger`），按同一时间区间核对；
2. 数据库：直接跑上面 SQL，与页面合计比对；
3. 差异排查顺序：签约时间为空的单 → 作废单 → 变更冲销 → 业务类型过滤。

## 常见问题

- **Q：合同金额含税吗？** 含税，取 `TAX_TOTAL`。
- **Q：为什么合同额和业绩报表的合同额不一致？** 看板对空签约时间做了兜底，业绩报表没有。
- **Q：审批中的合同算不算？** 不算，只有 1 和 11~15 计入。
- **Q：合同金额单位是什么？** 源表原值，展示层除以 10000 转万元。
