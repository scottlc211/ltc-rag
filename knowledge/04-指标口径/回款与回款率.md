# 指标：回款金额与回款率

> 归属：`crm-metric` · docKey：`crm/metric/collection-and-rate` · 证据基线：zhgj-crm-server（2026-11）

## 一句话口径

**业务已回款 = 回款单金额合计（审批通过）− 付款单金额合计（审批通过）**；回款率 = 已回款 ÷ 应收基准（执行金额或合同金额，二选一，系统未内置单一"回款率"字段）。

## 一、已回款金额的计算公式

回款原始合计（`DataBoardMapper.xml:23-35`）：

```sql
SUM(pc.PAYMENT_AMOUNT)
FROM t_payment_collection pc
WHERE pc.IS_DELETE = 0
  AND pc.PAYMENT_STATUS = 1
  AND pc.PAYMENT_DATE BETWEEN #{dateStart} AND #{dateEnd}
```

然后**减掉付款**（`DataBoardServiceImpl.java:384`）：

```java
BigDecimal totalReceivedAmount = receivedAmount.subtract(paymentAmount);
// 直营：directReceived - directPayment  （:386）
// 代理：agentReceived  - agentPayment   （:388）
// 有效：effectiveReceived - effectivePayment（:390）
```

付款合计（`DataBoardMapper.xml:45-57`）：

```sql
SUM(p.PAYMENT_AMOUNT) FROM t_payment p
WHERE p.IS_DELETE = 0 AND p.PAYMENT_STATUS = 1
  AND p.PAYMENT_DATE BETWEEN #{dateStart} AND #{dateEnd}
```

## 二、财务回款（另一个口径）

```sql
SUM(pfc.FINANCE_COLLECTION_AMOUNT)
FROM t_payment_finance_collection pfc
WHERE pfc.IS_DELETE = 0
  AND pfc.COLLECTION_DATE BETWEEN #{dateStart} AND #{dateEnd}
```

证据：`DataBoardMapper.xml:36-44`。

| 口径 | 表 | 日期字段 | 用途 |
|---|---|---|---|
| 业务回款 | `t_payment_collection` | `PAYMENT_DATE` | 销售业绩、看板 |
| 财务回款 | `t_payment_finance_collection` | `COLLECTION_DATE` | 财务对账 |

**两者数据源不同、日期不同，对不上是常态，不是 bug。**

## 三、回款率的算法（系统未内置字段）

> ⚠️ 重要：代码里**没有**叫"回款率"的字段或方法（全局搜索 `回款率` / `collectionRate` 无结果）。页面上如果显示了回款率，是前端或报表用下面几种组合算出来的。

常见两种分母，必须先确认是哪一种：

| 口径 | 公式 | 含义 |
|---|---|---|
| 执行口径（推荐用于资金分析） | `已回款 ÷ 执行金额` | 已发货执行部分收回了多少 |
| 合同口径（推荐用于销售考核） | `已回款 ÷ 合同金额` | 签下的合同收回了多少 |

其中"执行金额"=`SUM(gde.TAX_PRICE * t.DELIVERD_NUMBER) WHERE so.SUB_ORDER_STATUS IN (12,13)`（见 `crm/metric/contract-amount` 同源 SQL）。

## 四、未回款与未开票（都是相减）

```java
// DataBoardServiceImpl.java:397-406
执行未回款 = 执行金额 - 业务已回款
订单未回款 = 合同金额 - 业务已回款
执行未开票 = 执行金额 - 已开票金额
订单未开票 = 合同金额 - 已开票金额
```

注意"执行"与"订单"是两种基准，同客户两个"未回款"可以差很多。

## 五、数据源表

| 表 | 作用 |
|---|---|
| `t_payment_collection` | 回款单（`PAYMENT_AMOUNT`、`PAYMENT_STATUS`、`PAYMENT_DATE`、`BUSINESS_TYPE`） |
| `t_payment` | 付款单（用于冲减） |
| `t_payment_finance_collection` | 财务回款（`FINANCE_COLLECTION_AMOUNT`、`COLLECTION_DATE`） |
| `t_payment_receipt` | 开票（`RECEIPT_STATUS`） |
| `t_goods_sub_order` + `_detail` | 执行金额来源（状态 12/13） |

## 六、口径陷阱（必读）

1. **回款要减付款**：只加总回款单会偏大。出现负数回款也正常（退款/冲销单多）。
2. **状态必须 = 1**：`PAYMENT_STATUS = 1` 才是有效，0 审批中、2 驳回、4 撤销都不算。
3. **单位是元**：回款/付款表是 `decimal(22,2)` 元，展示层 ÷10000 转万元；而合同额源表语义是万元。跨指标相加前先统一单位（项目里最经典的坑之一）。
4. **有效回款 ≠ 回款**：还有一组 `effectiveReceivedAmount`（有效回款），它额外扣了 `effectivePaymentAmount`，业务含义与普通回款不同，报表选错字段就会对不上。
5. **直营/代理要分开看**：`directReceived`、`agentReceived` 是独立子口径，与 `totalReceived` 不可相加（会重复）。
6. **回款与开票无强绑定**：可以回款未开票（`业务回款未开票 = 已回款 − 已开票`），也可以开票未回款。

## 七、验证路径

1. 页面：`statisticalAnalysis` 数据中心 → 合同台账 → `collectionPrice.vue`（回款）/ `receiptPrice.vue`（开票）；
2. 数据库：分别跑回款、付款两条 SQL 相减；
3. 差异排查：状态过滤 → 日期字段（PAYMENT_DATE vs COLLECTION_DATE）→ 是否漏减付款 → 单位换算。

## 八、常见问题

- **Q：回款率怎么算？** 系统没有内置字段；执行口径 = 已回款/执行金额，合同口径 = 已回款/合同金额，先确认分母。
- **Q：已回款为什么比回款单合计少？** 减了付款单（`DataBoardServiceImpl.java:384`）。
- **Q：业务回款和财务回款差在哪？** 表不同、日期字段不同，前者业务确认到账，后者财务入账。
- **Q：未回款怎么算？** 执行未回款 = 执行金额 − 已回款；订单未回款 = 合同金额 − 已回款。
