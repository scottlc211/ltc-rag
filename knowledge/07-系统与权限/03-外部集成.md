# 外部集成：云客微信、实名制、开放接口

> 归属：`crm-sys` · docKey：`crm/sys/integration` · 证据：`yk_*` 表（云客）+ `c_project_*` / `c_engineering*`（政务源）+ `app/weChat`、`app/yunke`、`open` 控制器

## 一句话

外部集成分**三类**，性质完全不同：

| 类型 | 方向 | 例 | 数据落哪 |
|---|---|---|---|
| **营销触达** | 我方 ↔ 微信 | 云客（`yk_*`） | `yk_*` 表，与业务弱关联 |
| **政务数据** | 外 → 我方 | 省实名制、招投标、工程款 | `c_*` 清洗表 → `t_data_*` |
| **开放接口** | 外 → 我方 | `open` 包 | 直接调业务接口 |

## 一、云客微信（`yk_*`）

云客是**企业微信 SCRM**，把销售和客户的微信沟通记录下来。表结构很细：

| 表 | 字段 | 内容 |
|---|---:|---|
| `yk_user` | 17 | 云客-用户信息 |
| `yk_user_wechat` | 16 | 微信账号 |
| `yk_user_wechat_friend` | 25 | **微信好友关系** |
| `yk_user_wechat_friend_record` | 25 | **聊天记录** |
| `yk_user_wechat_friend_record_pat` | 10 | 拍一拍消息 |
| `yk_user_wechat_group_member` | 10 | 群成员 |
| `yk_user_wechat_voice` | 32 | 语音/视频记录 |
| `yk_user_follow_gather` / `yk_user_wechat_gather` | 17/16 | 跟进汇总、沟通汇总 |

### 用途

- 销售和客户的微信聊天**留痕**（合规要求）；
- 判断"有没有有效沟通"（辅助线索跟进判定）；
- 汇总沟通频次做管理分析。

### 和业务的关系是"弱关联"

`yk_*` 通过用户/手机号关联到线索和客户，**不是强外键**。所以"这个客户的聊天记录"要靠手机号或用户名匹配，可能有漏配。

## 二、政务数据（省实名制 / 招投标 / 工程款）

这部分**不是直接集成**，是经过数据中台的清洗管道（详见《数据中台》）：

```
省实名制 / 招投标 / 工程款 / 合同网签 / 物联网设备
   → c_* 清洗表 → t_data_* 业务数据 → 推荐 → 线索
```

对接状态字段在 `t_project_info` 上：`SMZ`（实名制）、`HJJC`（环境监测）、`SPJK`（视频监控）、`TJAQ`（塔机）、`SJJ`（升降机），明细表 `t_project_access_device` / `t_project_iot_device`。

## 三、开放接口

`com.zhgj.open` 包（2 个接口）+ `app/ai`（2 个）：给外部系统调我方的入口。

> 开放接口**必须做鉴权**，不能裸奔。当前实现方式需确认（见待确认）。

## 集成的共同问题

| 问题 | 表现 | 排查方向 |
|---|---|---|
| 数据重复 | 同一工程两条 | `t_data_engineering_merge` 合并记录 |
| 数据不同步 | 外部改了业务侧没变 | 业务侧是快照，靠 `DATA_*_ID` 关联 |
| 匹配不上 | 客户/工程关联为空 | 按手机号/信用代码/名称模糊匹配，人工兜底 |
| 集成失败无感知 | 数据没进来也没报警 | 看采集定时任务日志 |

## 常见问题

- **Q：客户微信聊天记录能查到吗？** 能，`yk_user_wechat_friend_record`，但要通过手机号/用户名匹配。
- **Q：工程上的"已对接实名制"是什么？** `t_project_info.SMZ=2` 表示已对接，只是状态标记，不影响业务流转。
- **Q：外部系统推数据给我方走哪个入口？** `open` 包，具体接口名单需按模块确认。
- **Q：为什么云客的数据我没权限看？** 云客数据挂在用户维度，受数据范围限制。
