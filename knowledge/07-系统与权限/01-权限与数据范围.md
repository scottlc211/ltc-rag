# 权限与数据范围：谁能看到谁的数据

> 归属：`crm-sys` · docKey：`crm/sys/permission` · 证据：`BasicController.checkUserCacheParams`（L128/L166）+ `t_user` / `t_role` / `t_department` / `t_user_area` DDL

## 一句话

系统有两层权限，**新人只盯着第一层，出问题都在第二层**：

- **功能权限**：能不能进这个菜单、能不能点这个按钮 —— 靠角色（`t_role`）；
- **数据范围权限**：能看到哪些人的数据 —— 靠 `cachePowerType`（4 档）。

"菜单有、点进去空的" 基本都是数据范围问题。

## 数据范围四档（`cachePowerType`）

| 值 | 范围 | 说明 |
|---:|---|---|
| 1 | **个人** | 只看自己名下的 |
| 2 | **部门及下属（不看联系人）** | 本部门 + 子部门，但**联系人字段脱敏/不返回** |
| 3 | **部门及下属（可看联系人）** | 同 2，且能看联系人 |
| 9 | **全公司** | 管理员/高管 |

> 2 和 3 的差别只有**联系人可见性**，这是刻意设计：防止主管把下属的客户联系人导走。

## 落地方式：`checkUserCacheParams`

所有列表接口的第一件事是调它：

```java
// BasicController:128
Map<String, Object> params = checkUserCacheParams(reqParams);
// 校验四个必备字段，缺一个直接返回 null（接口报无权限）
cacheUserId       // 当前用户
cacheDepartmentId // 当前部门
cacheUserType     // 用户类型
cachePowerType    // 数据范围 1/2/3/9
```

之后的 SQL 用这四个值拼 where 条件：

| `cachePowerType` | SQL 逻辑（等价形式） |
|---:|---|
| 1 | `USER_ID = #{cacheUserId}` |
| 2 / 3 | `DEPARTMENT_ID IN (本部门及子部门)` |
| 9 | 不加范围条件 |

### 重载版 `type` 参数

`checkUserCacheParams(params, type)` 的 `type` 改变**筛选依据**：

| type | 含义 |
|---:|---|
| 2 | 按部门区分"本部门 / 子部门" |
| 3 | 按数据权限区分"个人 / 子部门 / 全部" |
| 4 | **客户资产权限**：个人按"业务负责人 + 已转化客户"查，部门/全部直接查全量 |

> 客户模块用的是 type=4，所以"客户资产"页和"客户列表"页看到的数据可能不一样，这不是 bug。

### 区域隔离是第二条线

除了部门树，还有 `t_user_area`：用户绑定区域，数据按 `AREA_CODE` 过滤。线索分配、客户可见范围都会用到。

**所以一个人能看到什么 = 部门范围 ∩ 区域范围**（在配置了区域限制的情况下）。

## 三层校验的位置

```
1. 登录       → 拿 token，缓存用户信息（含 cachePowerType、角色）
2. 接口入口   → checkUserCacheParams 校验参数完整性，缺失即拒
3. SQL 层     → MyBatis 动态拼 where，按 powerType 加范围条件
```

> 注意：**Controller 不校验"这条数据是不是你的"**，靠 SQL 范围兜底。所以手写 SQL 忘了加范围条件 = 越权，这是本项目最常见的安全隐患。

## 常见问题

- **Q：菜单能进，列表是空的？** 数据范围问题：`cachePowerType=1` 但数据不在你名下，或部门没配对。
- **Q：主管看不到下属的客户？** 检查下属是否在同一部门树下（`t_department` 父子关系），跨部门不行。
- **Q：能看客户但看不到联系人？** `cachePowerType=2`，需要 3 或 9。
- **Q：客户资产页比客户列表少？** 资产页用 type=4，只算"业务负责人 + 已转化"。
- **Q：为什么换个区域就看不到数据了？** `t_user_area` 的区域限制。
- **Q：新增接口要做什么？** 列表类接口**必须**调 `checkUserCacheParams` 并把四个值带进 SQL，否则越权。

## 风险提示（需要开发注意）

`cacheUserId` / `cacheDepartmentId` / `cachePowerType` 都是**从请求参数里取**的。如果服务端没有在入口处用会话/token 覆盖这些值，客户端伪造 `cachePowerType=9` 就能看全公司数据。

⚠️ 需要确认：是否有拦截器/网关统一覆写这四个字段。**这是排查越权问题的第一站。**
