# 消息通知与待办：站内信、钉钉、短信

> 归属：`crm-sys` · docKey：`crm/sys/notice` · 证据：`t_notice`（21 字段）/ `t_notice_config` / `t_message_temp` DDL + management/notice + management/shortMessage

## 一句话

消息有**三个通道**，用同一套表控制：

- **站内信**（`t_notice`）——用户在系统里看到的红点/消息；
- **钉钉推送**——`t_notice.DINGTALK_PUSH_TYPE` 记录推没推；
- **短信**（`t_message_temp` / `t_message_his`）——验证码和营销短信。

## 站内消息 `t_notice`

| 字段 | 含义 | 取值 |
|---|---|---|
| `NOTICE_TYPE` | 通知类型 | **1 温馨提示 / 2 待办** |
| `LABEL_TYPE` / `LABEL_DETAIL_TYPE` | 标签类型 | 决定点击跳到哪 |
| `TITLE` | 标题 | |
| `CONTENT_PARAMS` | **内容参数**（5000 字符） | 存的是**参数**不是正文 |
| `LEVEL` | 优先级 | 1 低 / 2 中 / 3 高 |
| `IS_READ` | 已读 | 0 否 / 1 是 |
| `HANDLE_TYPE` | 处理状态 | **0 无需处理 / 1 未处理 / 2 已处理** |
| `HANDLE_USER_ID` / `HANDLE_TIME` | 处理人 / 时间 | |
| `DINGTALK_PUSH_TYPE` / `DINGTALK_PUSH_TIME` | 钉钉推送状态 | 0 无需推送 / 1 已推送 |

### 为什么 `CONTENT_PARAMS` 存参数不存正文

消息正文是**模板 + 参数**渲染出来的：

```
模板：XX 的合同《YY》已审批通过
参数：{userName: "张三", contractTitle: "XX项目合同"}
```

好处：多语言、多渠道（站内/钉钉/短信）复用同一套模板。坏处：**直接查表看到的是参数不是人话**，要渲染才能读。

## 待办（`NOTICE_TYPE = 2`）

待办 = 需要人处理的消息。判据是 `HANDLE_TYPE`：

| 值 | 含义 | 是否算"未处理待办" |
|---:|---|---|
| 0 | 无需处理 | 否 |
| 1 | 未处理 | **是** |
| 2 | 已处理 | 否 |

> "我的待办" = `NOTICE_TYPE=2 AND HANDLE_TYPE=1 AND IS_READ=0`。**已读未处理仍然是待办**，别只看 IS_READ。

## 通知配置 `t_notice_config`（24 字段）+ `_user`

控制"什么事件、发给谁、走哪个通道"：

- 配置粒度到**事件 + 角色/人**；
- `t_notice_config_user` 指定额外接收人；
- 关闭某类通知改这里，**不是改代码**。

## 短信 `t_message_temp` / `t_message_his`

| 表 | 用途 |
|---|---|
| `t_message_temp` | 发送**临时/队列表**（待发） |
| `t_message_his` | 发送**历史**（已发） |

短信用 `management/shortMessage` 2 个控制器 / 24 接口，含发送、模板、记录查询。

## 审批消息的特殊性

审批的待办**不完全走 `t_notice`**：`t_process_progress` 本身就是待办源（当前层级审批人 + 状态）。所以：

- 审批待办 → 查 `t_process_progress`（`AUDIT_STATE=0`）；
- 业务提醒 → 查 `t_notice`。

两套并存是历史原因，**做"全部待办"要合并两处**。

## 常见问题

- **Q：消息里显示的是 `{userName}` 这种占位符？** 模板没渲染，`CONTENT_PARAMS` 是参数不是正文。
- **Q：钉钉没收到？** `DINGTALK_PUSH_TYPE=0`（无需推送）或推送失败；也要看 `t_process_level.IS_PUSH_DINGTALK` 配置。
- **Q：消息已读但还在待办里？** 正常，看 `HANDLE_TYPE` 不是 `IS_READ`。
- **Q：不想收某类通知？** 改 `t_notice_config` / `t_notice_config_user`。
- **Q：短信没发出去？** 查 `t_message_temp`（还在队列）vs `t_message_his`（已发）。

## 待确认（⚠️）

1. 钉钉推送是同步还是异步（失败重试机制）。
2. `LABEL_TYPE` / `LABEL_DETAIL_TYPE` 的完整取值表（决定跳转目标）。
3. 消息是否会自动清理（无清理机制表）。
