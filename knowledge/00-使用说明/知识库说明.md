## 三、两类文件，别混用

| 类型 | 特征 | 怎么用 |
|---|---|---|
| **手写文档**（业务流程、代码地图、指标口径、表字典-业务分组） | 有判断、有业务解释、有坑 | 直接读，这是知识 |
| **机器生成文档**（接口清单、字段字典、表结构索引、高频表速查、定时任务、枚举、配置项） | 文件名带"清单/字典/索引/速查"，**勿手改** | 当字典查，Ctrl+F；改了下次重跑就被覆盖 |

机器生成的文档由两个脚本产出，代码变了重跑即可：

```powershell
python scripts/kb_inventory.py   # 接口 / 定时任务 / 枚举 / 配置项
python scripts/kb_schema.py      # 字段字典 / 表结构索引 / 高频表速查
```

## 四、知识库里的数据从哪来

| 来源 | 提供什么 | 更新方式 |
|---|---|---|
| `zhgj-crm-server` 源码 | 接口、Service、Mapper、表引用、定时任务 | 重跑脚本 |
| `zhgj_ltc.sql`（DDL 导出） | 375 张表、7014 个字段及注释 | 重新导出后重跑 `kb_schema.py` |
| 业务流程图（LTC 总流程 / 销售合同 / 代理合同） | 角色泳道、审批链、决策点 | 人工整理进流程文档 |
| 业务确认 | 口径、单位、阈值等代码看不出来的 | ⚠️ 标记待确认，不猜 |

## 五、写新文档的规矩

1. 照 `模板/模块文档模板.md` 的骨架写，**一节都不能少**；缺的写"❌ 未覆盖"。
2. 每个结论后面标证据（`文件:行号` 或表名），方便复核。
3. 看不出来的写进"待确认"，**不要用猜测填空**。
4. 写完更新 `00-使用说明/文档覆盖检查表.md`，把对应格子改成 ✅。

## 七、入库到知识库（RAG）

手写文档改了要重新入库，docKey 保持不变即视为版本更新：

```powershell
# 示例：更新合同流程
curl.exe -X POST "http://127.0.0.1:8081/v1/documents/text" `
  -H "Content-Type: application/json" -H "X-API-Key: 你的key" `
  --data-binary "@payload.json"
```

请求体：`{ "content": "...", "namespace": "ltc", "docKey": "crm/flow/contract", "title": "合同全流程" }`。

> 机器生成的**字段字典-全量.md（572KB）不建议整篇入库**，会把检索结果冲淡；查字段用 Ctrl+F 或按域切片后再入。
