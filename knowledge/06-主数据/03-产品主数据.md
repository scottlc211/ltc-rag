# 产品主数据：分类、底价、套餐、税率

> 归属：`crm-data` · docKey：`crm/data/product` · 证据：`t_product_info`（37 字段）/ `t_product_guide_price` / `t_product_package` / `t_product_tax_rate` DDL + management/product（7 控制器 / 46 接口）

## 一句话

产品主数据决定三件事：**报价怎么算**（单价/底价/税率）、**交付怎么走**（硬件/软件/安装、要不要 SN）、**业绩算给谁**（关联绩效产品）。报价页面上那些"低于底价"的警告，源头就在这里。

## 三个分类维度，别混

| 维度 | 字段 | 取值 | 决定什么 |
|---|---|---|---|
| **产品分类** | `PRODUCT_CATEGORY` | 1 硬件 / 2 软件 / 3 安装 | 走哪条交付线、金额归哪个小计 |
| **组合方式** | `PRODUCT_TYPE` | 1 套装 / 2 单件 / 3 产品包 | 报价时按套还是按件 |
| **类目** | `CATEGORY_ID` / `CHILD_CATEGORY_ID` | 两级类目 | 报表分类、税率 |

> 一个产品**同时有**分类和组合方式，不是二选一。比如"套装硬件"是 category=1、type=1。

另有两个**已弃用**字段：`BRAND`（用 `BRAND_ID`）、`CLASSIFY`（用 `CATEGORY_ID`）。老数据可能还有值，新代码不要用。

## 价格体系（三个价，别混）

| 字段 | 含义 | 用途 |
|---|---|---|
| `PRICE` | **标准单价** | 报价默认带出的价 |
| `FLOOR_PRICE` | **底价** | 低于它要预警/拦截（`IS_BELOW_FLOOR_PRICE=1`） |
| `LOWEST_PRICE` / `HIGHEST_PRICE` | 最低价 / 最高价 | **硬件拆分价**的上下限（对应 `2` 和 `3` 两种越界） |
| `OTHER_COMPANY_RENEWAL_FLOOR_PRICE` | 非我司利旧最低销售价 | 利旧场景专用 |
| `INSTALL_GUIDE_PRICE` | 安装指导价（元） | 安装费报价 |
| `CAN_PRICE_REDUCTION` | 是否允许降价 | 0 时不允许改价 |

### 这解答了一个老问题：底价从哪来

```
产品底价        → t_product_info.FLOOR_PRICE
区域差异        → t_product_guide_price（主表）+ t_product_guide_price_area（区域配置）
硬件拆分上下限  → t_product_info.LOWEST_PRICE / HIGHEST_PRICE
```

所以报价里 `IS_BELOW_FLOOR_PRICE` 的三种值有了明确来源：

- `1` 低于销售最低价 → 对比 `FLOOR_PRICE`（可能按区域取指导价）
- `2` 硬件低于拆分最低价 → 对比 `LOWEST_PRICE`
- `3` 硬件高于拆分最高价 → 对比 `HIGHEST_PRICE`

## 交付相关标记

| 字段 | 含义 | 影响 |
|---|---|---|
| `NEED_SN` | 是否需要 SN 号 | 发货时必须绑 SN，出库流程不同 |
| `IS_MUST_INSTALL_IMAGE` | 是否必须上传安装图片 | 安装单不传图不能完成 |
| `IS_MUST_MAINTENANCE_IMAGE` | 是否必须上传维护图片 | 维修单同理 |
| `UNIT` | 单位 | 台/套/项 |
| `SPECIFICATION` | 规格 | 合同附件展示 |

## 业绩归属：`RELATION_PRODUCT_ID`

产品上有一个"**关联绩效产品**"字段。报价明细、合同明细、发货明细都带这个字段——**业绩和提成按它归属，不按实际卖的产品**。

> 这是常见困惑："卖了 A 产品，业绩为什么算到 B？"因为 A 的 `RELATION_PRODUCT_ID` 指到 B。促销装、赠品、组合包都靠这个。

| `t_product_brand` | 品牌 |

## 税率怎么定

产品的 `TAX_RATE` **不在产品表上**，而在 `t_product_tax_rate` 里按**产品分类**配置。

```
报价/合同明细的 TAX_RATE ← 按 PRODUCT_CATEGORY 查 t_product_tax_rate
   存储口径：10000 = 100%，13% 存 1300
```

> 为什么按分类而不按产品：硬件 13%、软件 6%、安装服务 9%（举例），按类目配一次，新产品自动继承。

## 常见问题

- **Q：报价时提示低于底价，底价在哪改？** `t_product_info.FLOOR_PRICE`，区域差异看 `t_product_guide_price`。
- **Q：为什么这个产品不能改价？** `CAN_PRICE_REDUCTION = 0`。
- **Q：税率为什么和产品上看到的不一样？** 税率按分类配置在 `t_product_tax_rate`，产品表没有税率字段。
- **Q：卖的是 A，业绩算给 B？** 看 A 的 `RELATION_PRODUCT_ID`。
- **Q：套装和产品包有什么区别？** 套装是 `PRODUCT_TYPE=1`（一个 SKU），产品包是 `t_product_package`（多个 SKU 组合）。
- **Q：`BRAND` 和 `BRAND_ID` 用哪个？** 用 `BRAND_ID`，`BRAND` 已弃用。
