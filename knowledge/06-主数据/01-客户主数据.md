# 客户主数据：企业库、业务公司、代理商、授信

> 归属：`crm-data` · docKey：`crm/data/customer` · 证据：`t_customer_info` / `t_company_info` / `t_credit_limit` DDL + management/customer（2 控制器）+ ltc/customer（8 控制器）

## 一句话

系统里有**四种"公司"**，天天被混着叫"客户"：企业库（对方是谁）、业务公司（我方哪个主体）、代理商（渠道）、安装服务商（供应商）。分不清这四层，就会问出"为什么这个客户查不到合同"。

## 四种实体，先分清

| 实体 | 表 | 是谁 | 出现在哪 |
|---|---|---|---|
| **企业库** | `t_customer_info` | 甲方（客户公司） | 线索、商机、合同、开票 |
| **业务公司** | `t_company_info` | 乙方（我方交付主体） | 合同的"交付单位"、开票主体 |
| **代理商** | `t_customer_agent` | 渠道伙伴 | 代理商合同、备货、代理商订单 |
| **安装服务商 / 供应商** | `t_supplier`（企业库里的一种属性） | 给我方干活的公司 | 采购、安装派单 |

> 关键：**企业库是"唯一的公司档案"**，代理商、供应商都是企业库上的不同**属性**（`CUSTOMER_ATTRIBUTE`），不是独立档案。同一个法人既可以是客户又可以是代理商，看属性字段。

## 企业库 `t_customer_info`

| 字段 | 含义 | 取值 |
|---|---|---|
| `CUSTOMER_ID` / `CUSTOMER_NO` / `CUSTOMER_NAME` | 主键 / 编号 / 名称 | |
| `CUSTOMER_ATTRIBUTE` | **企业属性** | 1 签约客户 / 2 代理商 / 3 渠道商 / 4 安装服务商 |
| `CUSTOMER_PRIORITY` | **企业等级** | 1 重点 / 2 普通 / 3 潜在 / 4 未接触 |
| `CUSTOMER_TYPE` | 企业类型（工商口径） | 1 个人独资 / 2 个体工商户 / 3 其他 / 4 国有企业 / 5 外商投资（含港澳台）/ 6 普通合伙 / 7 有限责任公司 / 8 私营企业 / 9 联营企业 / 10 股份有限公司 / 11 集体所有制 |
| `CUSTOMER_SOURCE` | 企业来源 | 见枚举 |
| `PARENT_ID` | 上级单位 | **集团客户靠它串起来** |
| `TAXPAYER_NO` / `OPEN_BANK` / `BANK_ACCOUNT` / `LINK_PHONE` | 开票四要素 | 开票时直接带出 |
| `AREA_CODE` | 区域编码 | **线索分配、数据权限的分区依据** |
| `LNG` / `LAT` / `LOCATION_ADDRESS` | 经纬度定位 | 地图与撞单辅助 |

### 等级 vs 属性，别搞反

- **属性**（`CUSTOMER_ATTRIBUTE`）决定"**它是什么角色**"——客户？代理商？安装商？
- **等级**（`CUSTOMER_PRIORITY`）决定"**它有多重要**"——重点？普通？

等级影响跟进频率和资源倾斜，属性影响走哪条业务流程。**一个字段错，整个流程就错**。

## 业务公司 `t_company_info`

我方的开票/交付主体：

| 字段 | 含义 |
|---|---|
| `COMPANY_ID` / `CUSTOMER_ID` | 主键 / 对应的企业档案 |
| `COMPANY_SHORT_NAME` | 英文简称（**不是中文简称**） |
| `TAX_SCALE` | 1 一般纳税人 / 2 小规模纳税人 |
| `BRAND_ID` | 品牌 |
| `YEAR_INVOICED_AMOUNT` | **当年可开票金额**（额度控制用） |

> 合同上的 `COMPANY_ID` 指这张表，不是客户表。开票时"乙方"信息从这里取。

## 授信额度 `t_credit_limit`

| 字段 | 含义 | 坑 |
|---|---|---|
| `APPLY_TYPE` | 1 销售经理 / 2 代理商 | 两种申请主体 |
| `LIMIT_TYPE` | 1 正式额度 / 2 临时额度 | 临时额度有起止日期 |
| `BEFORE_AMOUNT` / `ADJUST_AMOUNT` | 调整前 / 调整额 | **单位：万元**，负数表示减少 |
| `LIMIT_STATUS` | -1 草稿 / 0 待审批 / 1 通过 / 2 不通过 / 4 撤回 / 5 作废 / **11 待执行 / 12 部分执行 / 13 已执行 / 14 已终止** | 审批通过≠生效，还有执行态 |
| `TEMP_LIMIT_START_DATE` / `_END_DATE` | 临时额度有效期 | 过期自动失效 |
| `ACCOUNTS_RECEIVABLE_START_DATE` | 应收账款起算日 | 账龄从这算 |

> **额度是万元，回款是元**——两套单位，做报表时必须换算，否则差 10000 倍。

## 代理商的独立性

代理商不是企业库里的一个标记就完事，`ltc/customer` 下有 8 个控制器专门管代理体系：

| 控制器 | 管什么 |
|---|---|
| `CustomerAgentController` / `CustomerAgentPersonController` | 代理商 + 代理商人员 |
| `CustomerAgencyController` / `CustomerAgencyPersonController` | 代理关系 + 关系人员 |
| `ChannelPartnerController` | 渠道合作伙伴 |
| `CustomerCompanyController` / `CustomerCompanyPersonController` | 公司 + 公司人员 |
| `CustomerLogController` | **客户变更日志**（谁改了什么） |

**代理关系**（`CustomerAgency`）是独立一层：代理商不是客户的属性，而是"谁代理谁"的关系表，一个代理商可以代理多个客户，一个客户也可能有多个代理商。

## 联系人

`t_clue_contact` 是**线索联系人**（跟着线索走），不是客户档案联系人。客户级联系人靠 `CustomerCompanyPerson` / `AgentPerson` 维护。

> 这就是为什么同一家客户在不同线索下有不同的联系人——联系人挂在线索上。

## 权限与数据范围

客户列表的可见范围由 `AREA_CODE`（区域）+ 归属关系决定：销售看自己跟进的客户，主管看本部门及下级，管理员看全部。代理商侧另有代理商归属过滤。

## 常见问题

- **Q：客户查得到，但合同查不到？** 合同挂的是 `CUSTOMER_ID`，检查合同上的客户 ID 和当前客户是不是同一个（重名企业很常见，要按 `CUSTOMER_NO` 或纳税人识别号核）。
- **Q：为什么这个客户既是客户又是代理商？** `CUSTOMER_ATTRIBUTE` 只存一个值，实际业务里可能两份档案或靠代理关系表区分。
- **Q：开票信息改了，合同里的没变？** 合同 `t_clue_contract_bill` 是**快照**，签合同时拷贝的，改主数据不会回改历史合同（这是设计如此）。
- **Q：额度单位？** `t_credit_limit` 是**万元**，回款/合同是**元**。
- **Q：同一集团下多个公司怎么关联？** `PARENT_ID` 指向上级单位。
