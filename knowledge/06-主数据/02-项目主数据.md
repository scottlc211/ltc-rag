# 项目主数据：工程阶段、评级、保护锁定

> 归属：`crm-data` · docKey：`crm/data/project` · 证据：`t_project_info` DDL（69 字段）+ `TClueBusinessMapper.xml:171` + management/project（7 控制器 / 72 接口）

## 一句话

工程（项目主数据）是**全系统的共享约束**：线索挂在它上面、商机在它上面判撞单、报价在它上面判保护期、合同在它上面算业绩。**一张工程被谁锁定，决定了所有销售能不能碰它**。

## 为什么项目主数据最重要

```
工程 t_project_info（一个工地）
   ├── 线索（多条线索可以指向同一工程）
   ├── 商机（撞单判定看 PROTECTION_LOCK）
   ├── 报价（保护期内不能报价）
   ├── 合同（合同 PROJECT_MASTER_ID）
   └── 发货 / 安装 / 回款（都带 PROJECT_MASTER_ID）
```

> 所以**工程是"客户 + 工地"的组合**，不是客户的下级。同一客户可以有多个工程，同一工程也可能被多个客户/代理商接触过。

## 核心字段

### 阶段 `PRJ_STATUS`

| 值 | 阶段 | 说明 |
|---:|---|---|
| 1 | 立项 | 工程生命周期的起点 |
| 2 | 备案 | |
| **3** | **（无）** | **系统里没有 3，这是历史约定** |
| 4 | 图审 | |
| 5 | 实施 | 施工阶段，商业价值最高 |
| 6 | 竣工验收 | |
| 7 | 招标 | |
| 8 | 投标 | |
| 9 | 评标 | |
| 10 | 中标 | |

> 阶段决定"什么时候该跟"，也影响线索分配的优先级。注意 `STAGE` 字段是**弃用**的，用 `PRJ_STATUS`。

### 评级 `RATING_KEY` / `RATING_SCORE`

| 等级 | `RATING_KEY` | 分数区间 |
|---|---:|---|
| S | 1 | ≥ 90 |
| A | 2 | 75–89 |
| B | 3 | 60–74 |
| C | 4 | ≤ 60 |

评级决定资源投入优先级，也是线索"平均分配规则"里"工程质量"维度的依据。

### 保护锁定 `PROTECTION_LOCK`（**全局最重要的一个字段**）

| 值 | 含义 | 对销售的影响 |
|---:|---|---|
| 0 | 无 | 任何人都可以跟 |
| 1 | **保护期内** | 撞单类型 2，商机保存可能被拦、报价可能被拦 |
| 2 | **已锁定** | 撞单类型 3，已有成交合同，别人不能再碰 |

配套字段 `PROTECTION_START_DATE`（保护开始日期）。保护期到期后从 1 变 0，或升级为 2（成交后锁定）。

> 这条链路贯通：`PROTECTION_LOCK` → `checkProjectCollisionInfo` → `repeatType 2/3` → 商机/报价被拦。**排查"为什么不能报价"先查这个字段**。

### 四方主体（工程上的公司）

| 角色 | 字段 |
|---|---|
| 施工单位 | `CONTRACTOR_CORP_ID` / `_NAME` / `_CODE`（`CONTRACTOR_CORP_IDS` 支持多个，逗号分隔） |
| 建设单位 | `BUILD_CORP_ID` / `_NAME` / `_CODE` |
| 监理单位 | `MANAGEMENT_CORP_NAME` / `_CODE` |

> 注意：**施工单位有单值 ID + 多值 IDS 两套**，多施工单位时以 IDS 为准。

### 数据来源

| 字段 | 含义 |
|---|---|
| `SOURCE` | 1 APP 创建 / 2 PC 创建 / 3 系统同步（ZHGD）/ 4 系统同步（YTH） |
| `PROJECT_CREATE_SOURCE` | 1 APP / 2 PC / 6 H5（**旧数据用 SOURCE，新数据用这个**） |
| `DATA_ENGINEERING_ID` / `DATA_PROJECT_MASTER_ID` | 数据中心来源的对应 ID |
| `ENGINEERING_ID` | 省实名制工程 ID |

**同一个工程可能有三条 ID**：本系统的 `PROJECT_MASTER_ID`、数据中心的、省实名制的。跨系统对账要按这三个 ID 分别匹配。

### 规模与投资

`AMOUNT`（**投资金额，万元**，是 varchar 不是数字）、`BUILD_SCALE`（建筑面积，平方米）、`PROPERTY_NUM`（建设性质类型）、`START_DATE` / `COMPLETE_DATE` / `WIN_BID_DATE`。

### 对接设备（数字化交付）

`SMZ` 实名制、`HJJC` 环境监测、`SPJK` 视频监控、`TJAQ` 塔机安全、`SJJ` 升降机安全——每个都是对接状态字段，配 `t_project_access_device` 明细。

## 接口分布

`management/project` 7 个控制器 / 72 接口；`app/project` 2 个 / 33 接口。主要是工程列表、详情、同步、评级、地址、联系人。

## 常见问题

- **Q：为什么这个工程我不能报价？** 查 `PROTECTION_LOCK`：1 保护期内 / 2 已锁定，都会拦。
- **Q：一个工程能有多条线索吗？** 能，线索与工程是多对一，撞单就是这么产生的。
- **Q：工程评级怎么算？** `RATING_SCORE` 分数对应 `RATING_KEY`，具体打分规则在评级模块（`t_project_rating_tmp` 是试算）。
- **Q：投资金额单位？** `AMOUNT` 是**万元**，且是字符串类型，排序/聚合前要转换。
- **Q：数据中心同步的工程和手工建的怎么区分？** 看 `SOURCE`（3/4 是同步）和 `DATA_*_ID` 是否有值。
- **Q：施工单位为什么有两个字段？** `CONTRACTOR_CORP_ID` 单值（历史），`CONTRACTOR_CORP_IDS` 多值（当前），新数据看后者。
