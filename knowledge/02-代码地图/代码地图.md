# 代码地图：从业务词找到代码与表

> 归属：`crm-code` · docKey：`crm/code/code-map` · 仓库：zhgj-crm-server

## 一句话

新人找代码的路径永远是：**业务词 → Controller → ServiceImpl → Mapper XML → 表**。这个项目四层一一对应、路径同名，认准一条就能顺到底。

## 四个模块各管什么

| 模块 | 职责 | 典型内容 |
|---|---|---|
| `zhgj-common` | 公共层 | 枚举（`DictEnum`/`CommonEnum`）、工具、异常 |
| `zhgj-service` | 领域服务 | 实体、DTO、部分 Service |
| `zhgj-management` | **主战场** | 213 个 Controller、1443 个类，Web/App 接口都在这 |
| `zhgj-scheduleTask` | 定时任务 | 线索回收、超时提醒、报表推送 |

业务代码都在 `zhgj-management/src/main/java/com/zhgj/app/` 下，**一个业务域一个包**。

## 目录结构（照这个找，不会有例外）

```
com.zhgj.app.clueBusiness.clue
├── controller/ClueController.java      ← 接口入口，@RequestMapping("/app/clue")
├── service/ClueServiceImpl.java        ← 业务逻辑（118KB，按方法名找）
├── dao/TClueMapper.java                ← MyBatis 接口
├── dao/TClueMapper.xml                 ← SQL（和接口同目录！）
└── entity/TClue.java                   ← 表映射
```

**关键约定**：Mapper XML 与 Mapper 接口**放在同一个 `dao` 目录**，不在 `resources` 下。全项目 260 个 XML 都是这样，找不到 SQL 时别去 resources 里翻。

## 命名规律（认名字就懂一半）

| 名字特征 | 含义 |
|---|---|
| `App*Controller` | 移动端接口（UniApp 用） |
| 无前缀 `*Controller` | Web 端接口 |
| `*ServiceImpl` | 业务实现，逻辑基本都在这里 |
| `t_*_detail` | 明细子表（合同明细、订单明细） |
| `t_*_record` | 流水表（跟进记录、分配记录），只增不改 |
| `t_*_contract` / `t_payment_*_contract` | 关联表，表达多对多（如回款核销到多张合同） |
| `t_business_settings` / `t_system_setting` | 配置表，业务规则开关都在这里，**改规则不用改代码** |

## 四步找人法（新人照着做）

**第 1 步：按业务词搜 Controller**
搜"合同" → 命中 `ClueContractController`、`AgentContractController`。

**第 2 步：看 Controller 的方法和 `@RequestMapping`**
`@RequestMapping("/app/clue")` + `@PostMapping("/add")` → 接口路径 `/app/clue/add`。

**第 3 步：跳进 ServiceImpl 找方法**
同名方法就是入口（`add` → `add(...)`）。

**第 4 步：看它调了哪个 Mapper 方法，去同名 XML 找 SQL**
SQL 里的 `FROM t_xxx` 就是这张表，`WHERE` 条件就是业务口径。

## 三个高频"找不到"的坑

1. **审批不在业务包**：合同/报价的审批流代码在 `process` 包（`ProcessServiceImpl`），业务包里只有"提交审批"那一行调用。
2. **定时任务在另一个模块**：线索回收、超时提醒在 `zhgj-scheduleTask`，业务包里搜"回收"是搜不到的。
3. **统计 SQL 只读跨域**：`dataBoard` 包直接 JOIN 几张业务表算指标，不写库，别在这找业务规则。

## 全项目表规模

- **293 张表**（从 260 个 Mapper XML 里解析出来的）。
- 引用最多的 10 张：`t_customer_info`(778)、`t_user`(569)、`t_clue_contract`(302)、`t_project_info`(298)、`t_company_info`(285)、`t_department`(272)、`t_customer_agent`(240)、`t_agreement`(232)、`t_clue`(198)、`t_goods_deliver`(163)。
- 这 10 张基本就是主数据 + 主干单据，**看懂它们等于看懂一半系统**。

## 常见问题

- **Q：业务逻辑到底在哪？** 90% 在 `*ServiceImpl`，Controller 只做参数接收和权限校验。
- **Q：SQL 写在哪？** Mapper XML，和 Mapper 接口同目录（`dao/`）。
- **Q：状态值 0/1/2 是什么意思？** 查 `zhgj-common` 的 `DictEnum` / `CommonEnum`，别猜。
