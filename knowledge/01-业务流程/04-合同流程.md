# 合同全流程（销售 / 代理商 / 备货）

> 归属：`crm-flow` · docKey：`crm/flow/contract` · 证据：`zhgj_ltc.sql` DDL + `ClueContractServiceImpl` + 销售/代理合同流程图

## 一句话

合同是 LTC 的**价值确认点**：报价赢单后生成合同，走审批 → 用印 → 生成订单 → 履约 → 开票回款。合同表 `t_clue_contract` 同时是**台账的主表**，所以它的字段口径就是全公司业绩口径。

## 三种合同，一套表

`t_clue_contract.BUSINESS_TYPE` 决定一切分支：

| 值 | 类型 | 谁创建 | 审批链 | 订单生成 |
|---|---|---|---|---|
| 1 | 销售合同（直营） | 销售经理/销售助理 | 合同审批 → 用印审批 | 审批通过自动生成销售订单 |
| 2 | 代理商合同 | 销售助理 | 代理商订单审批 → 合同审批 → 用印 | 代理商订单定期汇总 |
| 3 | 代理商备货合同 | 销售助理 | 同上 | 备货订单，走库存 |

> 三者共用 `t_clue_contract`，靠 `BUSINESS_TYPE` 区分；代理商场景才用 `AGENT_ID`、`DEPARTMENT_ID`、`USER_ID` 三个字段，销售合同这三个字段是 0。

## 角色与入口

| 角色 | 端 | 入口 | 能做什么 |
|---|---|---|---|
| 销售经理 | app / web | `/app/clue/contract`、`/web/clue/contract` | 创建、编辑、提交审批、申请用印/发货/开票 |
| 销售助理 | app | `/app/agent/contract` | 代理商合同、代理商订单 |
| 业务审批人 / 盖章人 | web | 审批中心 | 合同审批、用印审批 |
| 售后 | web | 发货/安装 | 发货相关事务 |
| 财务 | web | 开票/回款 | 开票、回款核销 |

## 主干流程

```
[销售] 报价赢单 → 创建合同(草稿) → 上传合同附件 → 提交审批
                                   ↓
[审批] 合同审批(外部投标/公司投标 → 业务审批人 → 其他相关人员 → 财务负责人 → 行政负责人 → 总裁办)
                                   ↓ 通过
                         合同状态 → 1 审批通过 → 自动生成销售订单
                                   ↓
[销售] 申请用印 → 用印审批 → 印章管理员盖章 → 上传用印文件 → 双方盖章
                                   ↓
[销售] 申请发货 → 发货审批 → 发货通知(售后) → 客户签收
                                   ↓
[销售] 申请开票 → 开票审批 → 财务开票 → 回款核销
```

## 状态机（`CONTRACT_STATUS`）

| 值 | 状态 | 谁会推进 | 备注 |
|---:|---|---|---|
| -1 | 草稿 | 销售创建 | 默认值，可改可删 |
| 0 | 待审批 | 提交审批 | 审批中，不能编辑 |
| 1 | 审批通过 | 审批人最后一人通过 | **触发订单生成** |
| 2 | 审批不通过 | 任一审批人驳回 | 可修改后重新提交 |
| 4 | 撤回 | 申请人主动撤回 | 只有申请人能撤 |
| 5 | 作废 | 管理员 | 终态 |
| 11 | 待签约 | 审批通过后 | 销售合同**无签约时间**时落这里 |
| 12 | 待履约 | 审批通过后 | 销售合同**有签约时间**（`SIGN_TIME`）时落这里 |
| 13 | 履约中 | 首批发货 | |
| 14 | 履约完成 | 全部发货+安装完成 | |
| 15 | 履约终止 | 人工终止 | 终态 |

**关键口径**：`11 待签约` 与 `12 待履约` 的区别就是 `SIGN_TIME` 有没有值（`ProcessMapper.xml` 的合同分支）。做"已签约"统计时两个都要算，做"待履约"只能算 12/13。

### 明细 `t_clue_contract_detail`

| 字段 | 含义 | 关键点 |
|---|---|---|
| `PRODUCT_ID` / `PRODUCT_CATEGORY` | 产品 / 分类(1硬件2软件3安装) | 分类决定走哪条发货线 |
| `PRODUCT_NUMBER` | 数量 | |
| `PRICE` / `TAX_PRICE` / `UNTAX_PRICE` | 标准单价 / 含税 / 未税 | **三个价并存，别混用** |
| `TAX_RATE` | 税率，**10000 = 100%** | 13% 存的是 1300 |
| `DISCOUNT` | 折扣，**9500 = 95 折** | |
| `IS_BELOW_FLOOR_PRICE` | 0 正常 / 1 低于销售最低价 / 2 硬件低于拆分最低价 / 3 硬件高于拆分最高价 | **底价比较的结果码** |
| `CHECK_FLOOR_PRICE` | 对比底价 | 比对用的基准价 |
| `NEED_SN` / `NEED_INSTALL` | 是否需要 SN / 安装 | 决定交付动作 |

### 开票信息 `t_clue_contract_bill`

甲方（`CUSTOMER_*`）与乙方（`COMPANY_*`）各 6 个字段：名称、纳税人识别号、地址、电话、开户行、账号。**开票前必须齐**，缺一个财务就打不出来。

### 关联表 `t_agreement`

框架协议，`BUSINESS_TYPE` / `AGREEMENT_STATUS` / `SIGN_DATE`。统计"签单数"时，走 `t_clue_contract` 是合同口径，走 `t_agreement` 是协议口径，**两者不能相加**。

## 核心调用链

```
addAppClueContract()        // 销售合同创建
  → 校验客户/商机/报价
  → t_clue_contract 插入（CONTRACT_STATUS = -1 草稿）
  → t_clue_contract_detail 批量插入（明细）
  → t_clue_contract_bill 插入（开票信息）

updateAppClueContractProcess()   // 提交审批
  → t_process_result 建审批实例
  → CONTRACT_STATUS = 0

审批全部通过
  → ProcessServiceImpl.processEndChangeData()
  → 按 BUSINESS_TYPE 落状态：备货/代理 → 1；销售无签约 → 11；有签约 → 12
  → 生成 t_goods_order

addClueContractChange()      // 合同变更
  → t_clue_contract_change_record
  → updateContractBillByChangeRecordId() 重算开票计划
```

## 业务规则

| 规则 | 实现 | 说明 |
|---|---|---|
| 底价校验 | `IS_BELOW_FLOOR_PRICE` + `CHECK_FLOOR_PRICE` | 低于底价必须走超额审批 |
| 折扣 | `DISCOUNT` 千分位（9500=95折） | 与税率同为整数存储，别当小数 |
| 税率 | `TAX_RATE` 万分数（1300=13%） | |
| 金额 | `decimal(22,6)` | 库里 6 位小数；看板展示时除 10000 转万元 |
| 变更是否需审批 | `getContractChangeType()` | 只改非金额字段可不走审批 |
| 合同模板 | `ClueContractDetailParams` 枚举 | 【客户名称】这类占位符 → 字段映射，1=主属性 2=数组内 |

## 审批链（来自流程图）

**销售合同**：合同审批分"外部投标 / 公司投标"两条支路 → 业务审批人 → 其他相关人员 → 财务负责人 → 行政负责人 → 总裁办 → 通过。

**代理商合同**：先走代理商订单审批（销售负责人 → 其他相关人员 → 财务负责人），再审合同、再用印。

**用印**：用印申请 → 用印审批（合同用印 / 非合同用印）→ 印章管理员盖章 → 上传用印文件 → 更新合同状态 → 双方盖章。

> 图上写的是具体人名（某总），实际审批人是配置出来的，以 `t_process_conf` 为准，不要按名字理解。

## 常见问题

- **Q：合同审批通过了为什么状态是 11 不是 12？** 因为没填 `SIGN_TIME`。签约时间一填，口径就变 12。
- **Q：合同金额是万元还是元？** 库里 `decimal(22,6)`，看板 `formatAmount()` 会除 10000 显示万元。**入库单位以业务确认为准**（⚠️ 待确认）。
- **Q：变更单要不要审批？** 看变更类型：动金额的必须走审批，只改联系人之类的不走。
- **Q：一张合同能开几次票？** 多张，开票计划在 `t_clue_contract_bill`，每次开票回写 `INVOICE_TOTAL`。
- **Q：代理商合同为什么没有订单？** 代理商订单是**定期汇总**生成，不是审批一通过就生成。

## 待确认（⚠️）

1. `TAX_TOTAL` 的存储单位（元 / 万元）——DDL 只有精度，没有单位说明。
2. 合同变更的"必须审批"判定阈值——`getContractChangeType()` 只能看到类型码，阈值可能在配置里。
3. 底价来源：按区域、按产品还是按客户等级——`CHECK_FLOOR_PRICE` 只是结果，取价逻辑需确认。
