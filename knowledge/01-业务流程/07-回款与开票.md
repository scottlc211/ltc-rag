# 回款与开票：核销关系、财务对账、红冲

> 归属：`crm-flow` · docKey：`crm/flow/collection-invoice` · 证据：`t_payment_collection` / `t_payment_collection_contract` / `t_payment_receipt` DDL + management/payment 8 个 Controller

## 一句话

钱这条链上有三件事，**表是分开的，不要混**：**回款**（客户付钱给我们）、**开票**（我们给客户开票）、**付款**（我们付给供应商）。回款和合同之间**不是直接挂字段，而是靠一张中间表核销**——这是理解整个模块的钥匙。

## 三个概念，三套表

| 业务 | 主表 | 关联表 | 方向 |
|---|---|---|---|
| 回款 | `t_payment_collection` | `t_payment_collection_contract` | 客户 → 我方 |
| 开票 | `t_payment_receipt` | `t_payment_receipt_contract` / `_product` | 我方 → 客户 |
| 付款 | `t_payment` | `t_payment_contract` | 我方 → 供应商 |

> 注意：`t_payment` 是**付款**（我们付出去），`t_payment_collection` 是**回款**（我们收进来）。名字很像，含义相反。

## 核销关系（重点）

回款不直接改合同金额，而是通过 `t_payment_collection_contract` 建立**多对多**关系：

```
一笔回款 t_payment_collection（PAYMENT_AMOUNT 总额）
   ├── 核销到 合同A 300 万（AMOUNT = 3000000）
   ├── 核销到 合同B 100 万
   └── 核销到 合同C 50 万
合计必须 = 回款金额，否则平不了账
```

中间表的四个关键字段：

| 字段 | 含义 | 为什么重要 |
|---|---|---|
| `CONTRACT_ID` | 核销到哪张合同 | 合同回款额由此汇总 |
| `PROJECT_MASTER_ID` | 对应工程 | 工程维度的回款统计 |
| `AMOUNT` | 本次核销金额（**分到这张合同的**） | 不是回款总额！ |
| `PAYEE_ID` | 收款单位 | 多主体收款时要区分 |
| `INCENTIVE_TYPE` | 激励核算状态：0 未计算 / 1 已计算 / 2 无需核算 | **提成/激励的计算标记**，漏了就没提成 |

> 常见误解："回款金额 = 合同回款额"。实际是 `SUM(AMOUNT)` 才是合同收到的钱。

## 回款从哪来：三条入口

`t_payment_collection.ADD_TYPE` 明确三种来源：

| 值 | 来源 | 说明 |
|---:|---|---|
| 0 | 手动添加 | 销售或财务手工录 |
| 1 | 导入 | 走 `t_payment_collection_import_tmp` 临时表 |
| 2 | 自动化创建 | 由财务系统同步生成 |

财务那条线是独立的：`t_payment_finance_collection`（财务回款信息）+ `t_payment_finance_collection_import` / `_import_detail`（导入批次与明细），业务回款靠 `FINANCE_COLLECTION_ID` 指回财务记录。

**这就是"业务回款"与"财务回款"两套账的来源**：财务导入的是银行流水，业务侧要把它核销到合同。对不上账时两边都要看。

## 状态机（`PAYMENT_STATUS`）

`-1 草稿 / 0 待审批 / 1 审批通过 / 2 审批不通过 / 4 撤回 / 5 作废`

与其他单据一致：审批通过（1）才参与核销统计，草稿和作废不算。

## 开票（`t_payment_receipt`）

| 关键字段 | 含义 | 注意 |
|---|---|---|
| `RECEIPT_CODE` / `INVOICE_CODE` | 开票单号 / **发票号码** | 发票号是财务给的，两者不同 |
| `RECEIPT_AMOUNT` / `UNRECEIPT_AMOUNT` | 已开票 / 未开票金额 | 未开票额是催票的依据 |
| `BUSINESS_TYPE` | 1 直营标准 / 2 代理商标准 | 与合同同口径 |
| `RECEIPT_TYPE` | 开票类型（字典） | 专票/普票等 |
| `INVOICE_HEADER` | 0 单位 / 1 个人 | 个人抬头不能抵扣 |
| `CUSTOMER_NAME` / `TAXPAYER_NO` / `ADDRESS` / `OPEN_BANK` / `BANK_ACCOUNT` | 甲方开票信息 | **从合同 `t_clue_contract_bill` 带过来** |
| `PROJECT_MASTER_ID` | varchar(2100) | **多工程逗号拼接**，和回款一样 |

### 一张合同可以开多次票

开票金额累计回写到合同 `INVOICE_TOTAL`。判断"还能开多少"看 `UNRECEIPT_AMOUNT` 或合同含税额减已开票额。

### 红冲

`t_payment_receipt_write_off`（开票红冲记录表）：发票开错不能删，**只能红冲**。红冲后原票作废、金额反向冲回，历史留痕。

## 退款与供应商付款

- 退款 `t_payment_refund` + `t_payment_refund_finance`：客户退钱，走审批，与合同/回款关联；
- 供应商付款 `t_payment_supplier`：采购付款，和回款的表结构类似但方向相反。

## 核心调用链

```
新建回款 POST /web/payment/collection/add
  → t_payment_collection 插入（PAYMENT_STATUS = -1）
  → 选择合同 → t_payment_collection_contract 逐条插入（AMOUNT 拆分）
  → 校验 SUM(AMOUNT) == PAYMENT_AMOUNT
  → 提交审批 → PROCESS_RESULT_ID + 状态 0
  → 通过后回写 t_clue_contract.PAYMENT_COLLECTION_TOTAL
```

## 常见问题

- **Q：合同上回款金额和回款单对不上？** 合同取的是 `SUM(t_payment_collection_contract.AMOUNT)`，只算审批通过（状态 1）的。
- **Q：一笔回款能核销多张合同吗？** 能，中间表就是干这个的，但合计必须等于回款金额。
- **Q：财务说回款到了，业务看不到？** 财务回款（`t_payment_finance_collection`）和业务回款是两套，要有人做核销才进业务侧。
- **Q：发票开错了能删吗？** 不能，走红冲（`t_payment_receipt_write_off`）。
- **Q：提成没算出来？** 看核销记录的 `INCENTIVE_TYPE` 是不是 0（未计算）。
- **Q：金额单位？** 回款 `PAYMENT_AMOUNT` 是 `decimal(16,2)`，**单位元，两位小数**；合同是 `decimal(22,6)`。
