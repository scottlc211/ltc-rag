# 报价：底价校验、超额审批与转合同

> 归属：`crm-flow` · docKey：`crm/flow/quotation` · 证据：`t_clue_quotation` DDL + `ClueQuotationServiceImpl`（2312 行）+ `WarningData:195` + `CommonEnum:2655`

## 一句话

报价是**商机的价格化**：把商机里的产品清单算成"含税/未税/硬件/软件/安装"五个金额，过程中要过**两道闸门**——工程撞单闸（保护期/锁定）和价格闸（底价/超额），过了才能提交审批，审批通过后才能转合同。

## 角色与入口

| 角色 | 端 | 入口 | 能做什么 |
|---|---|---|---|
| 销售 | app | `/app/clue/quotation` | 创建、改明细、提交审批、导出/分享 |
| 销售主管 | web | `/web/clue/quotation` | 列表、详情、导出、预警复检 |
| 审批人 | web | 审批中心 | 报价审批、超额审批 |

## 状态机（`QUOTATION_STAGE`）

| 值 | 状态 | 谁推进 | 说明 |
|---:|---|---|---|
| -1 | 草稿 | 销售创建 | 默认，可改可删 |
| 0 | 待审批 | 提交审批 | |
| 1 | 审批通过 | 审批人 | **可转合同** |
| 2 | 审批不通过 | 审批人驳回 | 改完可重提 |
| 4 | 撤回 | 申请人 | |
| 5 | 作废 | 管理员 | 终态 |

比合同简单：**没有 11/12/13 那套履约状态**，报价只有"审批生命周期"。

## 两道闸门

### 闸门一：工程撞单（`WARNING_CODE`）

报价创建时先查工程状态，命中就写预警位（`WARNING_CODE` 是 16 位字符串，按位标记）：

| 位 | 含义 | 阻断提示 |
|---:|---|---|
| 0 | 此工程已成交销售合同，已被锁定 | 不能创建报价 |
| 1 | 此工程已转化有效商机，**在保护期内** | 不能创建报价 |
| 2 | 报价中部分产品价格**低于最低销售价** | 不能创建报价 |
| 3 | 报价中硬件类产品**拆分价越界** | 不能创建报价 |

每种预警都有三档文案（`WarningData.QuotationWarningCodeEnum`）：中断提示 / 预警提示（"是否继续？"）/ 简述。**是阻断还是仅提示，取决于系统设置**，不是写死的。

### 闸门二：底价校验（三档策略）

系统设置 `restrictionProductPriceType` 决定底价怎么处理：

| 值 | 策略 | 代码行为 |
|---:|---|---|
| 1 | **不校验**（默认） | `isBelowFloorPrice` 强制置 0，明细上不体现 |
| 2 | 校验并**拦截** | 低于底价直接不允许保存 |
| 3 | 校验并**仅提示** | 写预警码 + 弹提示，仍可保存 |

底价比较的三种结果（`CommonEnum.ProductFloorPriceType`）：

| 值 | 含义 | 说明 |
|---:|---|---|
| 0 | 否 | 正常 |
| 1 | 低于销售最低价 | 整机价低于最低售价 |
| 2 | 硬件低于拆分最低价 | 只发生在**硬件**上，拆分价越下限 |
| 3 | 硬件高于拆分最高价 | 拆分价越上限，同样要拦 |

> 关键：**2 和 3 是"硬件拆分价"的两头越界**，不是"低于/高于"这么简单，别把 3 理解成"价太高不用管"。

### 超额审批（`IS_EXCESS`）

底价是"能不能卖"，超额是"折扣够不够格"。判定：

```
productInfoService.checkPrice(productInfo)
  失败 → clueQuotation.IS_EXCESS = 1，detail.IS_EXCESS = 1
  成功 → IS_EXCESS = 0
```

`IS_EXCESS = 1` 表示**超过报价等级**（折扣超过该销售等级的授权范围），必须走超额审批。这个标记在明细上也有，能定位到是哪一行超的。

## 金额计算规则

```
硬件小计 → HARDWARE_TAX_TOTAL
软件小计 → SOFTWARE_TAX_TOTAL（同产品多行按 PRODUCT_ID 合并数量）
安装类   → INSTALL_COST
TAX_TOTAL = 硬件 + 软件 + 安装
未税 = 含税 / (1 + 税率)
```

单价 → 金额按 `TAX_PRICE × PRODUCT_NUMBER × DISCOUNT / 10000` 计算。

## 核心调用链

```
POST /app/clue/quotation/add
  → 组装 ClueQuotation + 明细
  → 逐行：按 PRODUCT_CATEGORY 累加硬件/软件/安装小计
  → productInfoService.checkPrice()               // 超额判定 → IS_EXCESS
  → CommonProductUtils.checkProductListPriceV2()  // 底价判定 → IS_BELOW_FLOOR_PRICE
      → 按 restrictionProductPriceType 决定 拦截 / 提示 / 忽略
  → WarningData.changeCodeIndex()                 // 写 WARNING_CODE 位
  → 有阻断位则不落库；否则 insert 主表 + 明细
  → 提交审批：t_process_result + QUOTATION_STAGE = 0
```

## 报价转合同

审批通过（`QUOTATION_STAGE = 1`）后，合同创建时带 `QUOTATION_ID` 进来，合同的明细**从报价明细复制**。所以：

- 报价改了，**已生成的合同不会自动跟着变**；
- 排查"合同金额和报价不一致"，先看是不是合同创建后又手工改了明细。

## 常见问题

- **Q：为什么报价里看不到底价警告？** `restrictionProductPriceType = 1`（不校验），明细上的 `IS_BELOW_FLOOR_PRICE` 恒为 0。
- **Q：明明低于底价却能保存？** 策略配的是 3（仅提示），不是 2（拦截）。
- **Q：`IS_EXCESS = 1` 一定要审批吗？** 是，这是折扣超授权的标记，走超额审批分支。
- **Q：改完系统设置，老报价的预警怎么更新？** 调 `/web/clue/quotation/recheckWarning` 重算。
- **Q：硬件拆分价 3 是"太高"为什么也拦？** 拆分价虚高会扭曲毛利和绩效，所以两头都管。
