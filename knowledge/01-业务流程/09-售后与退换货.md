# 售后：维修派单与退换货

> 归属：`crm-flow` · docKey：`crm/flow/after-sales` · 证据：`t_goods_maintenance` / `t_goods_sub_maintenance` / `t_goods_return` DDL + `GoodsMaintenanceController` / `GoodsReturnController`

## 一句话

售后有**两条独立的线**，别混：

- **维修**：东西坏了，派人去修 → 走审批 + 派单（`t_goods_maintenance`）；
- **退换货**：东西不要了 / 要换 → 走退货单 + 回补库存（`t_goods_return`）。

安装是**履约的一部分**（第一次装），维修是**售后**（坏了再修），两者表结构相似但业务不同。

## 维修：`t_goods_maintenance`

### 状态机 `MAINTENANCE_STATUS`

| 值 | 状态 | 说明 |
|---:|---|---|
| -1 | 草稿 | |
| 0 | 待审批 | |
| 1 | 审批通过 | **触发派单** |
| 2 | 审批不通过 | |
| 4 | 撤回 | |
| 5 | 作废 | 终态 |
| 11 | **待派单** | 审批过了，还没定维修方 |
| 12 | **已派单** | 派给维修公司/人 |
| 13 | **已维修** | 完成，要传维护图片 |
| 14 | **部分派单** | 一次派不完，多批 |

> 和安装（`GoodsInstallStatus`）的状态码几乎一样，但**维修多了审批态**（-1/0/1/2/4/5），安装没有。

### 关键字段

| 字段 | 含义 | 说明 |
|---|---|---|
| `MAINTENANCE_CODE` | 维修单号 | |
| `ORDER_ID` / `GOODS_DELIVER_ID` | 订单 / 发货单 | 维修对象从哪来 |
| `PROJECT_MASTER_ID` | 工程 | 上门地址来源 |
| `IS_CHARGE` | **0 不收费 / 1 收费（向项目收费）** | 保修期内一般不收费 |
| `CHARGE_MONEY` / `REAL_CHARGE_MONEY` | 预估 / 实际费用 | 收费维修才有 |
| `PROCESS_RESULT_ID` | 审批实例 | 维修也要审批（涉及费用） |

### 子维修单

`t_goods_sub_maintenance`（21 字段）+ `_detail`：一张维修单可以派给多个维修方（不同地区/不同设备），拆子单执行。和发货的子订单是同一套思路。

## 退换货：`t_goods_return`

| 字段 | 含义 |
|---|---|
| `GOODS_RETURN_CODE` | 退货单号 |
| `GOODS_DELIVER_ID` / `ORDER_ID` / **`SUB_ORDER_ID`** | 支持退到**子订单**粒度 |
| `SUB_ORDER_PRODUCT_CATEGORY` | 1 硬件 / 2 软件需SN / 9 其他 |
| **`RETURN_TYPE`** | **1 退货 / 2 换货** |

明细 `t_goods_return_detail`（16 字段）记录退哪些产品、数量。

### 退货会连带三件事

1. **子订单状态变 21（已退货）**——不是订单层，是子订单层；
2. **库存回补**（`t_goods_inventory_detail`）；
3. **采购退货**（`t_goods_purchase.PURCHASE_TYPE = 3 常规采购退货 / 4 供应商直发退货`）。
4. **业绩冲减**——已关账月份的业绩要反关账才能冲。

## 常见问题

- **Q：维修为什么要审批？** 涉及是否收费、费用多少，所以要审批。保修期内免费也要留痕。
- **Q：维修单卡在"待派单"？** 审批过了但没人派，需要指定维修方。
- **Q：退货后订单状态没变？** 退货改的是**子订单**状态（21），订单本身可能还是 13 已收货。
- **Q：退货后库存没回来？** 看 `t_goods_inventory_detail` 有没有回补记录，可能卡在退货单未确认。
- **Q：维修和安装用同一批人吗？** 都用 `SUPPLIER_ID` 指企业库里的服务商，但单据是分开的。
