# 审批脊柱：配置驱动的流程引擎

> 归属：`crm-flow` · docKey：`crm/flow/approval-spine` · 证据：`t_process_conf` / `t_process_conf_trigger` / `t_process_level` / `t_process_result` / `t_process_progress` DDL

## 一句话

全系统只有**一套**审批引擎，报价、合同、超额、用印、发货、开票、回款、退款全走它。业务单据不自己写审批逻辑，只做两件事：**起实例**（往 `t_process_result` 插一条）和**接回调**（审批结束后改自己的状态）。

所以：**审批链不是代码写死的，是配置出来的**。改审批人要改表，不是改代码。

## 七张表，五个角色

| 表 | 角色 | 说明 |
|---|---|---|
| `t_process_conf` | **流程定义** | 一类审批的配置：类型、触发方式、是否自动通过 |
| `t_process_conf_form` | 表单定义 | 审批单上展示哪些字段 |
| `t_process_conf_trigger` | 触发条件 | 什么条件下走这条流程 |
| `t_process_level` | **层级模板** | 这条流程有几级、每级谁审、或签还是会签 |
| `t_process_result` | **实例** | 一次审批 = 一条记录 |
| `t_process_progress` | 实例层级 | 实例展开后的每一级 |
| `t_process_progress_audit` | 每人的确认 | 会签时每个人的意见 |

另有抄送 `t_process_copy_conf` / `_record` 和附件 `t_process_file`。

## 流程定义（`t_process_conf`）

| 字段 | 含义 | 关键点 |
|---|---|---|
| `PROCESS_CONF_TYPE` | 审批类型 | **1 商机报价 / 2 商机合同 / 3 超额报价 / 11 印章用印**（还有发货、开票等，按配置扩展） |
| `PROCESS_CONF_FORM_TYPE` / `_ACTION` | 表单类型 / 触发动作 | 决定"在哪张表单的哪个动作上触发" |
| `TRIGGER_TYPE` | **1 总是触发 / 2 条件触发** | 2 时看 `t_process_conf_trigger` |
| `IS_AUTO_AUDIT` | 是否直接通过 | **1 = 不起流程，自动审批通过** |
| `PRIORITY_LEVEL` | 优先级 | 多条配置命中时的排序 |
| `IS_ENABLE` | 是否启用 | 停用即不再触发 |

### 触发条件是"字段比较"配置

`t_process_conf_trigger` 的 `COMPARE_TYPE`：

| 值 | 比较方式 |
|---:|---|
| 1 | 等于 |
| 2 | 不等于 |
| 3 | 介于（用 `COMPARE_VALUE_ONE` 和 `TWO` 两个值） |
| 4 | 为空 |
| 5 | 不为空 |
| 6 | 包含 |

例如"合同金额 ≥ 100 万走总裁办"，就是表单字段 + 比较类型 3 + 两个边界值。

## 层级模板（`t_process_level`）

| 字段 | 含义 |
|---|---|
| `PROCESS_LEVEL` | 级别，**低级别先审，逐级上升** |
| `PROCESS_TYPE` | **1 人员 / 2 角色 / 3 部门** |
| `PROCESS_PERSON_IDS` / `PROCESS_ROLE_IDS` / `PROCESS_DEPARTMENT_IDS` | 对应类型的审批主体（逗号分隔） |
| `AUDIT_TYPE` | **1 或签（任一人通过即可）/ 2 会签（全部通过才过）** |
| `PARENT_ID` | 上级级别（支持分支） |
| `IS_PUSH_DINGTALK` | 是否推钉钉 |

> **或签 vs 会签**是最容易出错的点：或签一个人点了就过；会签要所有人都点，少一个就一直卡着。

## 实例（`t_process_result`）

| 字段 | 含义 | 坑 |
|---|---|---|
| `RELATION_ID` | 业务单据主键 | 合同/报价/发货的 ID |
| `BUSINESS_CODE` | 业务单号 | 给人看的 |
| `PROCESS_CONF_TYPE` | 审批类型 | 回调时靠它分发 |
| `SALES_USER_ID` | **审批关联销售** | 业绩归属靠它 |
| `APPLY_PERSON_ID` | 发起人 | |
| `APPLY_DATE` | **int 型**（20251212） | 不是 date 类型 |
| `RESULT_STATUS` | 0 待审批 / 1 通过 / 2 不通过 / 4 撤回 | 没有 5 作废 |
| `REDULT_TIME` | 结束时间 | **库里拼写就是 REDULT** |
| `IS_AUTO_AUDIT` | 是否自动审批 | 配置里 `IS_AUTO_AUDIT=1` 时置 1 |
| `CURRENT_PROGRESS_ID` / `PROCESS_PERSON_IDS` / `PROCESS_ROLE_IDS` | 当前层级快照 | 冗余字段，便于列表直接显示"待谁审" |
| `PROCESS_AUDIT_TYPE` | 当前层级或签/会签 | |

### 实例层级（`t_process_progress`）

`PROCESS_LEVEL` 顺序 + `AUDIT_STATE`（0 待审 / 1 通过 / 2 不通过）+ `PARENT_ID` 分支。

> ⚠️ 表里 `AUDIT_PERSON_ID` / `AUDIT_PERSON_ROLE_ID` / `AUDIT_PERSON_DEPARTMENT_ID` 三个字段**注释明确写了"弃用"**，实际确认人记录在 `t_process_progress_audit`。查"谁批的"别查这三个。

## 一次审批的完整生命周期

```
1. 业务动作（如提交合同审批）
   → 按 PROCESS_CONF_FORM_TYPE + ACTION 找 t_process_conf
   → 命中多条按 PRIORITY_LEVEL 排序
   → TRIGGER_TYPE=2 时校验 t_process_conf_trigger 条件

2. IS_AUTO_AUDIT=1？
   → 是：直接 RESULT_STATUS=1，业务侧立即改状态（不生成 progress）

3. 否：建 t_process_result（RESULT_STATUS=0）
   → 按 t_process_level 展开成 t_process_progress（逐级）
   → 推送钉钉（IS_PUSH_DINGTALK=1）

4. 审批人操作
   → 或签：任一人通过 → 该级 AUDIT_STATE=1
   → 会签：逐人写 t_process_progress_audit，全部通过才 AUDIT_STATE=1
   → 任一级不通过 → 整单 RESULT_STATUS=2，流程终止

5. 最后一级通过
   → RESULT_STATUS=1 + REDULT_TIME
   → 回调业务侧（ProcessServiceImpl.processEndChangeData）
       · 报价 → QUOTATION_STAGE=1
       · 合同 → 按 BUSINESS_TYPE/SIGN_TIME 落 1/11/12，并生成订单
       · 发货 → DELIVER_STATUS=1 → 生成 t_goods_order
```

## 审批类型与业务单据的对应

| `PROCESS_CONF_TYPE` | 业务单据 | 通过后动作 |
|---:|---|---|
| 1 | 报价 | `QUOTATION_STAGE = 1` |
| 2 | 合同 | 落 1 / 11 / 12 + 生成订单 |
| 3 | 超额报价 | 允许超额价格继续 |
| 11 | 印章用印 | 更新合同用印状态 |

> 发货、开票、回款、退款也有各自的类型值，具体值以 `t_process_conf` 实际数据为准（DDL 注释只列了 4 个）。

## 接口

`management/process` 3 个 Controller（38 接口）+ `app/process` 2 个（24 接口）：发起、待办、已办、详情、通过、驳回、撤回、催办、抄送。

## 常见问题

- **Q：提交后没有审批记录？** 该类型配置了 `IS_AUTO_AUDIT=1`，直接通过了，不生成流程。
- **Q：流程卡住没人能审？** 会签（`AUDIT_TYPE=2`）还有人没点；或审批人离职导致角色下无人。
- **Q：谁批的查不到？** `t_process_progress` 里那三个 `AUDIT_PERSON_*` 已弃用，查 `t_process_progress_audit`。
- **Q：为什么这个合同没走总裁办？** 触发条件没命中（金额/类型不满足 `t_process_conf_trigger`）。
- **Q：撤回后还能重提吗？** 能，重新起一个新实例（老实例 `RESULT_STATUS=4`）。
- **Q：审批通过但业务状态没变？** 看回调是否抛异常——`processEndChangeData` 失败会导致"审批通过但单据没动"。
