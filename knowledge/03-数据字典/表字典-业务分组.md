# 表字典：按业务域分组（全库 375 张，代码在用 293 张）

> 归属：`crm-data` · docKey：`crm/data/table-dictionary` · 依据：260 个 Mapper XML 解析

## 先记住三件事

1. **全库 375 张表**（DDL 导出），其中 **293 张在 Mapper 里被真正引用**，其余是历史/归档；主干只涉及 40 张左右。
2. **命名即语义**：`t_` 前缀 + 业务词 + 后缀。后缀含义见文末。
3. **表关系靠 `*_ID` 外键串**，没有数据库外键约束，靠代码保证——所以要按 Mapper 里的 JOIN 去理解关系。

## 主干表关系（ASCII）

```
t_clue(线索)
  └─1:1─ t_clue_business(商机)
            └─1:N─ t_clue_quotation(报价)
                        └─1:1─ t_clue_contract(合同) ──1:N── t_clue_contract_detail(合同明细)
                                    │                        └─1:N─ t_clue_contract_bill(账单/开票)
                                    ├─1:N─ t_goods_order(订单) ──1:N── t_goods_order_detail
                                    │           └─1:N─ t_goods_sub_order(子订单) ──1:N── t_goods_sub_order_detail
                                    │                       └─1:N─ t_goods_deliver(发货) ──1:N── t_goods_deliver_detail
                                    │                       └─1:N─ t_goods_sub_install(安装)
                                    └─1:N─ t_payment_contract ── t_payment_receipt(回款)
                                                              └─ t_payment_receipt_contract(核销关系)
```

## 一、线索域

| 表 | 作用 | 关键点 |
|---|---|---|
| `t_clue` | 线索主表 | `CLUE_STATUS`(0有效/1转化失败/2超时回收)、`USER_ID`(归属销售)、`AREA_CODE`(分配依据)、`IS_TRANSFORM`(是否已转化) |
| `t_clue_follow_record` | 跟进记录 | 只增不改，是"至少一次有效跟进"的判定依据 |
| `t_clue_fail_record` | 转化失败记录 | 失败原因，做失单分析 |
| `t_clue_allocate_record` | 分配流水 | 谁在什么时候把线索给了谁，配 `ALLOCATE_NUMBER` 看"烫手线索" |
| `t_clue_file` | 线索附件 | 报价单、图纸 |
| `t_clue_action_plan` | 行动计划 | 与 `t_business_settings` 配合 |

## 二、商机与报价域

| 表 | 作用 | 关键点 |
|---|---|---|
| `t_clue_business` | 商机主表 | 状态 1初步意向…6失单；撞单判定的载体 |
| `t_business_settings` | 商机业务配置 | 撞单规则、阶段配置等开关 |
| `t_clue_quotation` | 报价单 | 报价阶段、金额、审批状态 |
| `t_business_repeat*` | 撞单信息 | `BusinessRepeatServiceImpl` 读写，记录撞单数与撞单对象 |

## 三、合同域

| 表 | 作用 | 关键点 |
|---|---|---|
| `t_clue_contract` | 合同主表（**台账的核心**） | `CONTRACT_STATUS`、`TAX_TOTAL`(含税金额，万元)、`SIGN_TIME`(签约时间)、`BUSINESS_TYPE`(备货/代理/销售)、`USER_ID`(归属) |
| `t_clue_contract_detail` | 合同明细 | 产品行、数量、单价 |
| `t_clue_contract_bill` | 合同账单/开票计划 | 分期开票、回款计划 |
| `t_agreement` | 协议/框架合同 | `BUSINESS_TYPE`、`AGREEMENT_STATUS`、`SIGN_DATE`，与线索、客户、项目关联 |

> 台账口径差异就在这两张表：`t_clue_contract` 是合同口径，`t_agreement` 是协议口径，两者都统计"签单数"时口径不同。

| `t_goods_sub_install` | 安装单 | 安装派单、安装完成 |

## 五、资金域（回款与核销）

| 表 | 作用 | 关键点 |
|---|---|---|
| `t_payment_receipt` | 回款单（**台账回款口径**） | 实收金额，单位**元** |
| `t_payment_receipt_contract` | **回款核销关系** | 一笔回款核销到多张合同/发票，多对多就靠它 |
| `t_payment_collection` | 收款单/应收 | |
| `t_payment_collection_contract` | 收款与合同关联 | |
| `t_payment_contract` | 合同回款计划 | 应收计划表 |
| `t_payment` | 付款 | |
| `t_payment_supplier` | 供应商付款 | |
| `t_payment_finance_collection` | 财务收款 | 看板取数会用到 |

> **金额单位陷阱**：合同金额存**万元**，回款金额存**元**。做汇总时必须统一，看板里 `formatAmount()` 会再除 10000。

## 业务动作 → 该看哪张表（速查）

| 你要查 | 主表 | 通常还要 JOIN |
|---|---|---|
| 线索归属谁 | `t_clue` | `t_user`、`t_department` |
| 线索为啥没分配 | `t_clue`（`USER_ID=0`） | `t_area`、`t_user` |
| 商机阶段 | `t_clue_business` | — |
| 报价与审批 | `t_clue_quotation` | `t_process_result` |
| 合同签了多少 | `t_clue_contract` | `t_customer_info` |
| 发货到哪一步 | `t_goods_deliver` | `t_goods_order`、`t_goods_deliver_detail` |
| 回款核销到哪 | `t_payment_receipt_contract` | `t_payment_receipt`、`t_clue_contract` |
| 业绩算给谁 | `t_process_result`（`SALES_USER_ID`） | `t_clue_contract`、`t_payment_receipt` |

## 常见问题

- **Q：合同金额单位？** `t_clue_contract.TAX_TOTAL` 是万元，回款是元。
- **Q：回款和合同怎么对上？** 通过 `t_payment_receipt_contract`，一笔回款可对多张合同。
- **Q：项目上的"保护锁定状态"在哪？** `t_project_info`，取值：已锁定 / 保护期内 / 无。
- **Q：表里字段不确定？** 以对应 Mapper XML 的 SELECT 列表为准，别猜。
