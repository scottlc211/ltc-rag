## 一句话

## 接口的两个统一约定

### 1. 返回统一 `JsonData`

所有接口返回 `JsonData`，前端按 `code`/`msg`/`data` 处理。分页返回 `PageInfoUtils`（带 `total`/`list`）。

### 2. 入参两种风格

| 风格 | 长什么样 | 占比 |
|---|---|---|
| **Map 风格** | `HashMap<String, Object> reqParams` | **大多数** |
| DTO 风格 | `XxxDTO dto` + `Errors errors`（带校验） | 新增/编辑类 |

> Map 风格的代价：**字段名只能靠文档和前端对齐**，IDE 无法提示。所以查字段要去看前端调用或 Mapper XML。

## 怎么从业务找到接口（三步）

```
1. 业务词 → 模块        合同 → agreement / contract；发货 → goods/deliver
2. 模块 → 控制器        打开"接口清单"对应模块小节
3. 控制器 → 具体接口     看中文说明列，找动词匹配的那个
```

例：查"合同列表" → `management/agreement` → `ManagementAgreementController` → `POST /web/agreement/list`。

## 常见坑

- **Q：路径里的 `ANY` 是什么？** 用 `@RequestMapping` 未限定 HTTP 方法，GET/POST 都能进。
- **Q：`/web/` 的接口 App 能调吗？** 技术上能（同一个服务），但**权限和参数结构不同**，业务上不该混用。
- **Q：找到接口但不知道参数？** Map 风格的接口看 Mapper XML 里用了哪些 key，或直接看前端调用。
- **Q：接口存在但 404？** 检查网关/前缀改写（有些部署会加 context-path）。
- **Q：同一个功能有两个接口？** App 端和 PC 端各一套，属正常。
